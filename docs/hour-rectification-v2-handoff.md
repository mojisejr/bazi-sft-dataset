เอกสารนี้สรุป**สิ่งที่เราสร้างไว้ให้**, เหตุผลเบื้องหลังทุกการตัดสินใจ, **ผลทดสอบจริง (รวมจุดที่ยังพลาด)**, และ**คำแนะนำว่าควรเดินทางไหนต่อ** — เพื่อให้คุณเจริญศักดิ์ (เจ้าของทั้งความรู้โหราศาสตร์และ engine) รับไปทำต่อได้ทันที

## 1. ภาพรวม — feature นี้คืออะไร

**สอบยาม (Hour Rectification)** = ระบบช่วยหา **ยามเกิด (時柱 / ช่วง 2 ชั่วโมง)** สำหรับคนที่**ไม่รู้เวลาเกิด** โดยไม่ใช้ LLM ตอน runtime

- **input:** วันเดือนปีเกิด + เพศ + **เหตุการณ์ชีวิตที่มีปี** 2-4 อย่าง (แต่งงาน/มีลูก/เปลี่ยนงาน/เจ็บหนัก/สูญเสีย/ย้ายถิ่น)
- **output:** เวลาเกิดโดยประมาณเป็น**จุด** (เช่น `~08:00`) + ช่วง (`07:00-09:00`) + confidence: **beta**
- **หลักการ:** คำนวณดวง 12 ยามของคนคนนั้น → ให้ "ตารางกฎ (rules)" ให้คะแนนว่ายามไหนที่ดวงจร/ปีจร (大運/流年) เข้ากับเหตุการณ์จริงมากสุด → ยามนั้น = คำตอบ

**ข้อค้นพบสำคัญระหว่างสร้าง (goo):** ดวง 12 ยากต่างกัน**แค่เสายาม (時柱)** เท่านั้น — ปี/เดือน/วัน/大運 เหมือนกันหมดทุกยาม → **กฎที่ discriminate ได้ ต้อง anchor ที่เสายาม + 藏干(ราศีแฝง)ของเสายาม** เท่านั้น (กฎที่อิงเสา fixed = ให้คะแนนเท่ากันทุกยาม = ไร้ประโยชน์)

## 3. โครงสร้างที่เราสร้างไว้ (Clean Architecture — additive ล้วน ไม่แตะ engine/code เดิม)

```
src/lib/bazi/hour-rectification/

│   ├── signals.ts                  สกัด YearSignal จากดวง+ปีเหตุการณ์ (合/冲/刑/害/桃花/เทพเจ้าสิบ เทียบเสายาม)
│   ├── interaction-tables.ts       ตาราง 刑/半三合 แบบ classical-correct (local ไม่แตะ engine กลาง)
│   ├── rules.ts   ★★★              ← ★ ตารางกฎ = จุดที่คุณเจริญศักดิ์แก้ (ดูข้อ 6)
│   ├── scorer.ts                   ruleScorer.score() — เดินกฎทุกยาม×ทุกเหตุการณ์ → จัดอันดับ + tie-break
│   └── time-mapper.ts              แปลงยาม → เวลา (จุด=กลางช่วง + ช่วง 2 ชม. / ขยาย 3 ชม. ถ้ายามติดกันสูสี)
├── adapters/
│   └── timeline-adapter.ts         buildHourChartFacts() — คำนวณดวง 12 ยาม (buildLifeTimeline×12)
├── run-events.ts                   orchestrator: input → 12 ดวง → scorer → time-mapper → ผล + inconclusive guard
├── ui/RectifyByEventsExperience.tsx  หน้าจอ: ฟอร์มเหตุการณ์ → ผลเวลา + expert view (ดูกฎ/คะแนน)
└── index.ts

src/app/api/bazi/rectify-hour/events/route.ts   sub-route ใหม่ (ไม่แตะ route v1)
src/app/rectify-hour/events/page.tsx             หน้า v2
src/styles/features/rectify-hour.css

tests/  (deterministic ล้วน — ไม่มี LLM flaky)
├── rectification-signals.test.ts · rectification-rules.test.ts · rectification-scorer.test.ts
├── rectification-time-mapper.test.ts · rectification-events-api.test.ts
```

## 4. API contract (ถ้าต่อ FE)

```
POST /api/bazi/rectify-hour/events
  { birthDate:"YYYY-MM-DD", gender, province, events:[{type,year}] × 2-4 }
→ { status:"result", timeEstimate:{point,rangeStart,rangeEnd,spansAdjacent}, rankedYams:[top3], ... }
  | { status:"need_events" }        // events < 2
  | { status:"inconclusive", rankedYams } // คะแนนเสมอ/ยามไม่ติดกัน → ไม่มั่วเวลา
```
`year` = ค.ศ. (ปีจร annualGanzhi ใช้ ค.ศ.) — ถ้ารับ พ.ศ. จาก user ต้อง -543 ก่อน

## 5. ⚠️ ผลทดสอบจริง — จุดที่ยัง "ไม่แม่น" (ซื่อสัตย์ 100%)

เราทดสอบกับดวงจริงของฟีม: **เกิด 3 ม.ค. 1989 เวลา 08:45 = ยามจริง 辰 (มะโรง, 07:00-09:00)** · เหตุการณ์จริง: แต่งงาน 2012 + มีลูก 2022 (เอาเวลาเกิดออก แล้วให้ระบบสอบเอง)

**ผลลัพธ์ = พลาด:**
```
อันดับที่ระบบให้:
#1 午 (มะเมีย 11-13)  score 6   ← ระบบเดา (ผิด)
#2 子 (ชวด)          score 5
#3 酉 (ระกา)         score 4
#4 辰 (มะโรง 07-09)  score 3   ← ความจริง — ตกอันดับ 4 เสมอกับอีก 3 ยาม
```

**สรุปตรงๆ:** ยามจริง (辰) ได้แค่อันดับ 4/12 · ระบบเดา 午 (ห่าง 2 ยาม) · **ยังไม่แม่นกว่า v1 อย่างมีนัยสำคัญ** · n=1 ให้ % ไม่ได้ แต่**เคสจริงที่มี = พลาด**

**ทำไมพลาด:** `rules.ts` ที่ทีมเราเขียน = **hypothesis จาก classical + LLM ไม่ใช่วิธีจริงของสำนักคุณเจริญศักดิ์** → น้ำหนัก/เงื่อนไขกฎยังไม่ตรงศาสตร์จริง · **สถาปัตยกรรมถูก แต่ "เนื้อกฎ" ต้องคนที่รู้จริงมาเติม**

## 6. 🎯 จุดที่คุณเจริญศักดิ์เข้ามาทำต่อ — `rules.ts`

`src/lib/bazi/hour-rectification/domain/rules.ts` ถูกออกแบบให้เป็น **swappable artifact** — แก้ไฟล์เดียว ไม่ต้องรื้อ engine

โครงกฎ 1 ข้อ:
```ts
{
  id: "MAR-1",
  event: "marriage",
  when: (signal) => /* เงื่อนไข deterministic บน chart fact เช่น 流年 六合 กิ่งยาม */,
  weight: +3,          // + สนับสนุน / − ขัดแย้ง
  because: "ปี {year} 流年 合 เสายาม → เข้าจังหวะแต่งงาน",
}
```

**signal ที่ใช้ได้** (engine คำนวณให้แล้วผ่าน `signals.ts`): 六合/三合/半三合 · 冲/害/刑 · 桃花 · เทพเจ้าสิบ (十神) · 大運/流年 — **ทั้งหมดเทียบกับเสายาม+ราศีแฝง**

**วิธีทดสอบว่ากฎที่แก้แล้วแม่นขึ้นไหม (dry-run):**
```
1. แก้ rules.ts (เพิ่ม/ลบ/ปรับน้ำหนัก)
2. เปิด /rectify-hour/events → ใส่ดวงที่รู้เวลาจริง + เหตุการณ์
3. ดูว่าเดายามตรงไหม (มี expert view โชว์กฎที่ fire + คะแนน)
4. วนปรับจนแม่นกับเคสจริงหลายๆ เคส
```

**หมายเหตุกฎที่เรา mark ไว้:**
- `major_loss` = กฎอ่อนสุด (mark `weak`) — คุณเจริญศักดิ์ตัดสินว่าคงไว้/แก้/ตัด
- `interaction-tables.ts` (刑/半三合) เราเขียน classical-correct แบบ local — เช็คได้ว่าตรงสำนักคุณไหม

## 7. 💡 คำแนะนำ — ควรเดินทางไหนต่อ

เราวิเคราะห์แล้วว่า ความแม่นของสอบยามมาจากได้แค่ **3 แหล่ง**: (1) ตำราคลาสสิก (เราลองแล้ว—ยังพลาด), (2) dataset จริงเยอะๆ แล้ว learn ทางสถิติ, (3) **ความรู้ผู้เชี่ยวชาญจริง** ← คุณเจริญศักดิ์

**เส้นทางที่เราแนะนำ (เรียงตามพลัง):**

1. **[แนะนำสุด] คุณเจริญศักดิ์เขียนวิธีสอบยามจริงลง `rules.ts`** — คุณคือคนเดียวที่มีทั้งความรู้ศาสตร์จริง + เขียนโค้ดได้ → เสียบวิธีจริงลงตารางกฎ แล้ว dry-run เทียบเคสจริงของคุณ

2. **สะสมเคสจริง 10-20 คน** (รู้เวลาเกิด + เหตุการณ์+ปี) — เป็น validation set วัด % จริง + จูนกฎมีหลักฐาน (ไม่ใช่เดา)

3. **[คำถามที่อยากฝากถาม] production DB ของ mootech มี label เหตุการณ์ชีวิตของ user ไหม?** — ถ้ามี (เวลาเกิดจริง + เหตุการณ์+ปี) เราจะ learn กฎทางสถิติได้เลย โดยไม่ต้องเดา → อันนี้จะเปลี่ยนเกมมาก

4. **[ทางเลือก] Calibration console** — ถ้าอยากให้ซินแสที่ไม่เขียนโค้ดแก้กฎได้ด้วย เราออกแบบไว้แล้ว (แปลง rules เป็น data + หน้าแก้กฎ + หน้าทดสอบเคสจริงโชว์ %) — บอกทีมฟีมได้ถ้าต้องการ

## 8. สิ่งที่ทีมฟีมส่งมอบ (สรุป)

✅ **ยานพาหนะที่ถูกต้อง**: harness deterministic, additive, ทดสอบแล้ว, swappable rules, มี dry-run + expert view + inconclusive guard + time-mapper ที่ไม่มโนนาที (เคารพขีดจำกัดศาสตร์ = ละเอียดสุดระดับช่วง 2 ชม.)
⚠️ **สิ่งที่ยังขาด**: "เนื้อกฎจริง" — ต้องความรู้ของคุณเจริญศักดิ์ (หรือ dataset จริง) มาเติม · ตอนนี้ยัง **beta** อย่าเพิ่งใช้ตัดสินจริง

เรา**หยุดตรงนี้โดยตั้งใจ** เพราะการที่ทีมเราเดากฎเพิ่ม = overfit ไม่ใช่ความแม่นจริง · ส่งต่อให้เจ้าของความรู้ = ถูกทางที่สุด 🙏
